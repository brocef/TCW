I want to create a new TCW top-level feature which is an AGENTS.md builder. Just how the work lifecycle system is polymorphic and lets the repository manager construct prompt generating mechanisms for the various lifecycle stages, I want to do the same for a project's AGENTS.md.

Use case is as follows. Let's say there's a project that is being worked on by three people: a software engineer, a UI/UX engineer, and a product designer. I would like a system that, when these three people first pull the repo and start the repo setup instructions, they run a TCW command to generate an AGENTS.md file (CLAUDE.md also generated, symlink to AGENTS.md). The contents of the agents file would depend on *who* is running the TCW generate command. The command would ask the caller what role they are. If the software engineer runs it, they choose "engineer" in the TCW prompt, and then TCW would generate an AGENTS.md file with instructions related to doing full-stack development. If the UI/UX engineer runs the command and specifies their role (say, "ui/ux") then the generated AGENTS.md would be different. Perhaps it would have instructions like "do not build out any backend features, if you are building a prototype of a new feature then all API calls should be stubbed and return mock data." Lastly, the product person's AGENTS.md file would be even more different and say "I am not an engineer, so you must communicate with me without any technical programming language or jargon. Do not build out any backend functionality. If you are making a new feature prototype, stub all API calls and return mock data."

What do you think?
