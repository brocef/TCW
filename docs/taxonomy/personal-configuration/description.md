Configuration that belongs to one person rather than the team: a user-wide file and a `.tcw/tcw-config.local.yaml` kept out of version control, and environment overrides, `TCW_<KEY>__<PROJECT>`, layered over the team's `.tcw/tcw-config.yaml`, and a personal manifest, `.tcw/tcw-manifest.local.yaml`, saying where other projects are on that person's machine, read before the committed one. The local files record their format version like every file in `.tcw/`; the user-wide file, shared by every TCW a person installs, does not. In a linked git worktree with no personal file of its own, the main checkout's is used. A person can add to or replace a stage's instructions, add commands that run after an item moves, change a procedure's text, name their own Jira credential variables, say who they are, list child projects of their own in the project's `.tcw/tcw-config.local.yaml` (never in the user-wide file), and place connected projects where they are on their disk, without changing what the rest of the team gets. These settings apply to the project a command acts on and to each project it inherits configuration from, so a person's credential names for a parent reach its children; a project read for itself takes only the overrides naming it.
