# v0.20.0

Developer changelog for the next version. Technical and precise; grouped by
category.

## Added

- `.github/workflows/test.yml` — the repo's first CI. `pytest` on
  `ubuntu-latest` across Python 3.11 (the `requires-python` floor) and 3.14 (the
  local development interpreter). `fail-fast: false` so both legs always report;
  `push` is scoped to `branches: ['**']` so a tag push does not run the suite
  twice. Exposes `workflow_call`. No Node setup — nothing in `pytest` shells out
  to it.
- `.github/workflows/release.yml` — publishes to PyPI on a `v*` tag via Trusted
  Publishing (`id-token: write`, `environment: pypi`, no API token). Gated on the
  test workflow, then on the pushed tag matching `project.version` in
  `pyproject.toml`.
- `README.md` gains a **Releasing** section: the cut-and-push ritual, the
  one-time pypi.org pending-publisher and GitHub environment configuration, and
  the fact that a PyPI version number is spent whether or not the job that
  uploaded it went on to succeed.

## Changed

- **Distribution renamed `tcw` → `tcw-cli`** (`pyproject.toml`). `tcw` on PyPI is
  an unrelated project ("tiny contest winners application", last released
  2023-01). Only the distribution name moves — `[project.scripts]` still installs
  a `tcw` command, `packages.find` still ships a `tcw` import package, and
  `tcw --version` still reads `tcw/__init__.py`. Wheels build as
  `tcw_cli-<version>-py3-none-any.whl`.
- `skills/tcw-plugin/references/doctor.md` — step 2 checks both
  `tcw_cli-<ver>.dist-info/` and `tcw-<ver>.dist-info/`; new step 6 covers a
  stale pipx `tcw` package sitting alongside `tcw-cli` (report as clutter, do not
  remove).
- `skills/tcw-plugin/references/setup.md`, `README.md` — the `pip install`
  collision warnings now name `tcw-cli`.

## Fixed

- `scripts/session_bootstrap.sh` — the editable-install guard looked up
  `distribution("tcw")` only. Under the renamed distribution that raises
  `PackageNotFoundError`, which the caller reads as "not editable" and answers
  with `pipx install --force` over a developer's checkout, silently, every
  session. It now tries `tcw-cli` then `tcw`, first name found deciding.

## Internal

- `tests/test_session_bootstrap.py` no longer keeps its own copy of the probe;
  `_editable_probe()` extracts it from the shell script, so the text under test
  is the text that ships and there is no second copy to drift.
- The probe is now covered directly, against synthetic `dist-info` trees under
  `python -S`, across seven cases: either name editable, non-editable,
  `direct_url.json` absent, neither installed, and both installed in each
  precedence direction. The pre-existing fixture tests stub the owning
  interpreter with `exit 0`/`exit 1`, so they exercised the script's branches
  without ever running the Python that chooses between them —
  `test_real_editable_checkout_is_left_alone` is the only test that ran it, and
  on a machine whose `tcw` is a version-manager shim it takes an earlier branch
  and never reaches the probe.

## Verified, no change required

- `pipx install --force` against the renamed clone repoints an existing
  `~/.local/bin/tcw` owned by a pipx package named `tcw`, leaving that package
  orphaned. The orphan cannot reclaim the link (pipx declines to overwrite an app
  link owned by another package), and its install spec is a local path, so
  `pipx upgrade` resolves from the path rather than PyPI. No migration step was
  added to `session_bootstrap.sh`.
- `tcw/serve/dist` package data reaches the wheel: a clean build carries the 5
  tracked files, and installing that wheel into an empty venv yields a working
  `tcw --version` with `serve/dist/server.cjs` and `serve/dist/client/index.html`
  under site-packages. The gitignored `client/.vite/manifest.json` is not packed
  (the `dist/**/*` glob skips dot-directories).
