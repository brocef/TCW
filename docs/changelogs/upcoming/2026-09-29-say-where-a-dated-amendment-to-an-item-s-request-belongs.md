## Changed

- Where a later amendment to an item's request goes is now stated once and
  consistently: appended to `initial-request.md` under `## Added <YYYY-MM-DD>`,
  never to `intake.md`; an intake-only item gets its request written first;
  past backlog, where the `request` stage no longer runs, the request is written
  directly (a body edit, which promotes the item); with a spec or plan present
  it must reach them — in review via `rework.md` and then the spec — since
  `implement` and `verify` never read the request. New "Amending a
  request" section in `skills/work/references/commands.md` and
  `docs/guide/work.md`; one line in `skills/work/SKILL.md`.
- `tcw/work/procedures/create-work.md` no longer sends item amendments to
  `intake.md`, which contradicted the raw-intake rule; inbox entries are
  unchanged.
- `tcw/work/prompts/request.md` (and the skill's stage summary) tell a re-run
  of the `request` stage to keep dated `## Added` sections.
- `skills/work/references/commands.md`: the paragraph on body writes and
  promotion moves back under "The body surface"; it had drifted to the end of
  "The documentation gate".
