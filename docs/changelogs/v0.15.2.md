## Added — fold-into-unpushed-version option (`bfa8d99`..)

- `skills/documentation-sync/scripts/unpushed-version.sh` — the gate for the new
  option, and the skill's first non-markdown asset. Resolves the latest matching
  tag via `git describe`, then classifies it: published if `git ls-remote --tags`
  finds it on **any** configured remote, or if `git branch -r --contains` shows
  its commit already rode out on a remote branch; unpublished if there is no
  remote at all. Every remote is queried — checking only the upstream/origin
  reported foldable for a tag pushed to a second remote, which is precisely the
  unsafe case. An unreachable remote is recorded and the sweep continues, so a
  definitive "published" from a live remote outranks UNKNOWN; only a clean sweep
  of reachable remotes with no hit yields foldable. Exit `0` foldable / `1` not /
  `2` some remote unreachable — the agent reads the code, never the prose, and
  `2` is deliberately not collapsed into `1` so an offline check can't be misread
  as "safe to rewrite the tag".
- `skills/documentation-sync/references/cut-version.md` — new "Folding into an
  unpushed version" section: re-confirm the gate, `git tag -d`, merge
  `upcoming.md` content into the existing `v{version}.md`, answer triggers for
  the commits since the tag, reset `upcoming.md`, extend the hash ranges,
  commit, re-tag at HEAD, verify with `git tag --points-at HEAD`. Version-bearing
  files are untouched — the number does not change.
- `tests/test_unpushed_version_script.py` — eleven cases over tmp_path repos with
  local bare remotes (no network): no tag, tag at HEAD, unpushed with later
  commits, pushed tag, tag pushed to a *non-default* remote, unpushed tag whose
  commit is on the remote branch, unreachable remote, published-beats-unreachable,
  tag on a side branch, a custom tag glob, and the executable bit.
