# v1.2.2

### Internal

- **The CI suite is green again.** Every run since v1.0.0 was cut failed — the
  last green one was the v0.21.1 fold on 2026-08-13 — which also meant the
  `release` workflow's `test` gate never passed and **seven** tagged versions
  never published to PyPI: 1.0.0, 1.0.1, 1.0.2, 1.0.3, 1.1.0, 1.2.0 and 1.2.1.
  PyPI had been serving 0.21.1 that whole time. Three independent causes, all
  in the tests rather than in shipped code, and all of them invisible on a
  developer's machine:

  - **No committer identity on a bare runner** (13 failures in
    `tests/test_store_publication.py`). Fixtures configure `user.email`/
    `user.name` into the repositories they create themselves, but not into the
    ones TCW *clones* — `tcw provision` checks a store out, and a clone inherits
    no local config. Those commits had been falling through to the developer's
    global identity; on CI there is none, and git refused with `fatal: empty
    ident name`. A new autouse `_git_identity` fixture in `tests/conftest.py`
    sets `GIT_AUTHOR_*`/`GIT_COMMITTER_*` for the whole suite. Environment, not
    `git config --global`, deliberately: config would also answer the
    `git config --get user.email` fallback in `tcw work start`'s claimant
    resolution and mask a precondition some tests exercise.
  - **The same missing identity reached `tcw work start`'s claimant fallback**
    (`test_every_cli_write_refuses_with_one_wording_and_writes_nothing`). With
    no identity anywhere the command refuses with `claimant identity required`
    rather than the repository refusal the test asserts. It now sets
    `TCW_WORK_OWNER`, so its subject is the repository guard rather than the
    host's identity. (The refusal still writes nothing either way, so the
    contract held; only the wording assertion did not.)
  - **`printf '\xff\xfe'` is a bashism**
    (`test_invalid_utf8_is_replaced_rather_than_fatal`). `run_generate` uses
    `shell=True`, i.e. `/bin/sh` — dash on Debian and on the runner — whose
    `printf` has no `\x` escape and emitted the four characters literally, so
    the test fed the hook valid UTF-8 and had nothing to replace. Now POSIX
    octal (`\377\376`), identical in dash and bash.
  - **The wheel test had no build backend on the 3.14 leg**
    (`test_the_prompts_are_in_the_built_wheel`). It builds with
    `--no-build-isolation` to keep the suite off the network, which requires
    setuptools to be present already; setuptools has not been bundled with the
    interpreter since 3.12, so the test passed on 3.11 and failed on 3.14 with
    pip exit 2. `setuptools>=61` — the version the build backend already
    declares — is now part of the `dev` extra.
