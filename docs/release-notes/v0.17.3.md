# v0.17.3

User-facing release notes for the next version. Plain language — no jargon or
internal module names.

## You can now keep finished work out of git

Some projects want their finished and abandoned work items on disk but not in
the repository — the record is useful locally, but it is internal history that
does not belong in what the project ships.

Add `docs/work/completed/` and `docs/work/discarded/` to your `.gitignore` (and
run `git rm -r --cached` on them once, to drop what git already has), and
finishing an item now does the right thing: the item moves into its folder, the
files stay on disk, and the commit removes them from the repository instead of
re-adding them somewhere new. Everything else is unchanged — the item still
shows up in `tcw work list --all`, still opens with `tcw work show`.

Previously the ignore looked like it worked but quietly did nothing: every
completed item came straight back into the next commit.

If you don't ignore those folders, nothing about finishing an item changes.
