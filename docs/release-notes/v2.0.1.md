# v2.0.1

## Ask for a lifecycle stage by name

Reading a stage used to mean naming the skill and then telling it which stage you
wanted: `tcw-work-stage spec my-item`. You already knew the stage — it is why you
reached for the skill — so five new skills have it built in.

- `tcw-work-stage-request`
- `tcw-work-stage-spec`
- `tcw-work-stage-plan`
- `tcw-work-stage-implement`
- `tcw-work-stage-verify`

Each takes just the work item, and even that is optional. Ask without one and you
still get the stage's instructions, with a placeholder where the item reference
would appear. That is useful for reading what a stage involves before you have an
item to run it on.

`tcw-work-stage` has not changed and still takes the stage id, so it remains the
way to read the two stages without their own skill: `inbox`, which runs before an
item exists, and `postmortem`, which already has `tcw-post-mortem`.

As before, these skills only read. They do not check whether the stage is allowed
to run — `tcw work stage gate` is still what refuses.

These are Claude skills. Under Codex the two commands they wrap work exactly as
they always have.
