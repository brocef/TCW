# v1.2.2

### If you are upgrading from 0.21.1, this release brings you everything since

**Seven tagged versions never made it to PyPI** — 1.0.0, 1.0.1, 1.0.2, 1.0.3,
1.1.0, 1.2.0 and 1.2.1. The automated test run that guards publishing had been
failing since 1.0.0 was cut, so the upload step never ran and
`pip install tcw-cli` kept serving **0.21.1**. That is fixed, and this release
carries all of that work with it in one go.

**Read the [0.21.X → 1.0.0 migration guide](../migration-guide-0.21.X-to-1.0.0.md)
first.** 1.0.0 is a major release and carries one breaking change — an empty
prompt list (`prompt: []`) is now refused by `tcw validate`. Everything still
runs either way while you fix it; only `tcw validate` complains.

What you missed, in short — the details are in the notes for each version:

- **1.0.0** — TCW tells you what to do at each lifecycle stage itself, through
  `tcw work stage <stage> <item>`, whichever agent you drive it with; that
  knowledge used to live only in the Claude plugin. Plus `tcw work scaffold`
  for starting drafts of any lifecycle document.
- **1.0.1 – 1.0.3** — fixes across the web viewer, including clearer handling
  of links that point at another project's board.
- **1.1.0** — a project can say which repository its work store lives in, and
  `tcw provision` fetches it, so a fresh checkout of just your code can still
  reach its board, specs and plans.
- **1.2.0** — the falsification rule.
- **1.2.1** — relative store paths resolve correctly inside a git worktree.

### Fixed

- **Nothing about how TCW behaves has changed in 1.2.2 itself.** The only
  changes are to the project's own tests and development setup, which is what
  was keeping releases from being published.
