As a user, I set one configuration key of one project from an environment variable, so a script, a CI job or a shell session can change a personal setting without editing any file.

**The name follows from the key and the project.** `TCW_<KEY>__<PROJECT>` holds the key's parts and the project's ID in capitals, joined by `_`, each `-` written `_`, with `__` between the key and the project: `TCW_USER_NAME__APP` sets `user.name` of project `app`, and `TCW_WORK_JIRA_CREDENTIALS_EMAIL_ENV__MY_PROJ` sets `work.jira.credentials.email-env` of `my-proj`. A variable starting `TCW_` and holding `__` that names no key, or is not written in that form, is a problem.

**Only what a personal file may set.** A variable may set `user.name`, a stage's `prompt` and `post` lists, a procedure's list, and the names of the two Jira credential variables. One that would set anything else, such as `work.tags`, the backend, a stage's `status` or `pre`, a store location or `children`, is a problem saying it is a shared key.

**Its value is read by the key's type.** A name is taken as written, so `TCW_USER_NAME__APP=no` is the text `no`. A list or a mapping is read as YAML, such as `TCW_WORK_STAGES_SPEC_PROMPT__APP='[{blob: hello}, {inherit: true}]'`; `null`, YAML that cannot be read and a value of the wrong kind are problems, and no message shows the value. A variable naming a stage changes only what it names, and the more specific variable wins: `TCW_WORK_STAGES_SPEC_PROMPT__APP` beats `TCW_WORK_STAGES_SPEC__APP` whatever their order. A `file:` binding from a variable is read from the root of the project it names.

**Where it applies.** The variables are the last personal layer, after `.tcw/tcw-config.local.yaml`, for the project a command acts on and for each project it inherits from; a project read for itself, such as the owner of an item named by its full identifier, takes the variables naming it too. A problem with a variable stops every command in the active project with exit 1, and `tcw validate` reports it as an error at `environment`. `TCW_NO_PERSONAL_CONFIG=1` turns the variables off, with the personal files. `tcw work stage prompt` names the variables that changed the list it composed, and a failed `post` command names the variable it came from.
