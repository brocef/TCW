As a user, I run `tcw config show` to see the configuration a command in this project actually runs with: TCW's own defaults, the team's `tcw-config.yaml` and my personal files, merged. It prints YAML on standard output that reads back as that configuration, and writes nothing. One value is deliberately printed differently: a value under a key ending in `-env` that is not shaped like an environment variable's name is printed as `(value not shown)`, because it is most likely a token pasted where the variable's name belongs. An entry that stands for TCW's own text is printed `- builtin: true` with a comment naming the packaged file it stands for.

`tcw config show --origin` adds a comment after every value and list entry naming where it came from — `built-in`, `project`, `user: <path>` or `local: <path>` — and ends with a comment line for each value my personal files set that was not used: `# refused:` for a key that belongs to the team, `# skipped:` for a Jira credential name in a project that does not use Jira. In that closing block every value under a key ending in `-env` is shown as `(value not shown)`, in case a token was pasted there by mistake.

With a problem in the configuration, plain `show` stops with exit 1 like every other command. `--origin` still prints everything it could merge, so I can find the line that is stopping the others, then exits 1 with the problems on standard error. A `tcw-config.yaml` that cannot be read leaves it nothing to print.
