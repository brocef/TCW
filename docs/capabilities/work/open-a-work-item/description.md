As a user, I run `tcw work new "<title>"` (with an optional piped body) to create a backlog item; the tool prints its generated slug (to stdout) and, to stderr, where the item was created. The generated slug is always usable: a title that reduces to nothing becomes `untitled`, and a very long one is truncated, so no title I can type produces an unusable slug or a failed command. Piped text is preserved as the item's raw intake, so the tool prints the path to that file for me to open; created with nothing piped, the item has no body file yet and the `request` stage is what writes one. I can pass `--blocked-by <refs>` (comma-separated slugs or external strings) to attach blockers at creation time.

A write that Git refuses — a lock another process holds, a hook that says no — is rolled back: whatever the command created is removed, and whatever was already there is left as it was. So a failure leaves the project as it found it, with nothing to clean up by hand.
