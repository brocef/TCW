As a user, I file work in another project from the one I am in with `tcw work new "<title>" --project <id>`. The other project must be one my `tcw-config.yaml` declares and that is on this machine. The item lands in that project's inbox, so its owners decide what to do with it; piped text becomes its request, and `--priority` is the only property I may set from here. The command prints the new item's full slug, `<id>/<folder>`.

I can also mark an item there as blocked by one of mine: `tcw work edit <my-item> --blocks <id>/<folder>` adds my item to that item's `blocked-by`, and never creates anything.

When the other project keeps its items in Jira, `new --project` creates a ticket in that project's Jira inbox, with TCW Project set to its id. If the project is on this machine, has a work store with no uncommitted changes, and its workflow can move the ticket on, the ticket also becomes an item there: the command makes its folder, moves it to the request stage and prints its slug. Otherwise the ticket stays in the inbox, the command prints the ticket's key and exits 0, and stderr says why. For a Jira-mode project that is not on this machine, a `jira` block in my `connected-projects` entry for it names its site, Jira project, inbox status, credential variables and TCW Project field; the site and the credential variables always come from the same file.

Both refuse (exit 3) and write nothing in the other project when it is not declared here, or is declared as an upstream project (which is read-only from here, `tcw://C/cli/read-from-an-upstream-project`). `edit --blocks`, and `new --project` into a filesystem-mode project, also refuse when it is not on this machine, has no work store, or has uncommitted changes in its work store; that last check reads git without taking any lock in that repository. `new --project` into a Jira-mode project refuses only when the project is neither on this machine nor described by a `jira` block. What delegation writes is left uncommitted in the other project's repository, and the command says which files, so that project's owners commit it.
