As a person triaging a Jira-mode project, I see the tickets waiting to become items with `tcw work tickets list`: tickets in the configured Jira project at the inbox status with no TCW Item, widened by `work.jira.inbox-query` when it is set, and only those `adopt` would accept. It prints one key per line; `--json` adds each ticket's summary, status, creation time, reporter, link and description, and stderr gives the count and the query that ran.

`tcw work tickets adopt <KEY>` makes such a ticket an item: it sets the ticket's TCW Project and TCW Item, writes the item's folder, moves the ticket to the request stage's status if it was at the inbox status, and runs the request stage's `post` hooks once. It refuses, changing nothing, a ticket in another Jira project, one that belongs to another TCW project, one that is already an item, one further along the workflow, and one the workflow cannot move to request. An adoption, or a `new`, that stopped part way is finished by running `adopt` again. In a filesystem-mode project both commands are usage errors.
