As the person who set a project up in Jira mode, I run `tcw validate --remote` to check, with reads only, that the Jira project matches what TCW needs: the credentials work and the project is readable; the TCW Project and TCW Item fields, the estimate fields and the other fields TCW sets are on the create and edit screens of each issue type in use; every mapped priority and the `Blocks` link type exist; every stage's status exists; and the workflow offers one transition for every move TCW makes, with no screen field TCW cannot fill. It also checks each item folder against its ticket, and runs the stage, reference and record checks that need an item's stage or links.

Findings go to stdout, one per line, as `<severity>: <where>: <message>`; anything that could not be checked, such as a move with no ticket to sample, is a warning starting `unchecked:`; what passed is said on stderr. It exits 0 with warnings only, 1 with any error, and 5 when Jira cannot be reached, and it never changes Jira. In a filesystem-mode project `--remote` is a usage error.
