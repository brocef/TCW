As a user, I run `tcw work edit <slug> --blocked-by <refs>` to record that named items (or external dependencies) block my item, `--blocks <refs>` to record that my item blocks named items, and `--unblocked-by <refs>` to remove blockers that have been resolved. The tool guards against self-blocking and cycles, including a cycle that runs through items in other connected projects, and checks the blockers of a new item as well as edits to an existing one. When the check cannot read an item on the way — its `state.yaml` is damaged, or two folders hold its slug — the edit is refused, naming that item, because whether it makes a cycle is unknown. Blockers are stored in the item's data, not as a separate folder or status.
