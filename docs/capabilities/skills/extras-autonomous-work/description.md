As a user or agent, I ask the `extras-autonomous-work` skill to take one or more work items to completion without me answering along the way. After confirming the set of items and their order once at the start, the agent drives each item through the `commands-drive-work-to-completion` skill, one after another. Wherever the lifecycle would ask me — a review, an open question, the verify decision, a closeout choice — it gives the same self-contained question to read-only advisors, weighs their answers as arguments rather than votes, and decides itself.
Which advisors, how work is reviewed and how an item is closed out come from my project's `unattended-work` procedure. With nothing configured, that is TCW's default: two advisors, Codex and a separate Opus subagent; it never cuts a version or pushes to a remote. My project replaces it under `work.procedures.unattended-work`.
Whatever my project configures, it stops and reports only on a hard blocker: credentials or another step only a person can take, anything that cannot be undone, a question about what the product should be, spending on my paid accounts, advisors who disagree about a choice that cannot be undone, or a spec that contradicts the code. It records each question, what each advisor said and what it chose in the item's `outcome.md`, so the run can be reviewed afterwards.
