As a user or agent, I open the `taxonomy` skill to learn how to keep my project's taxonomy through the `tcw taxonomy` command: declaring Vocabulary terms (the concepts the project reasons about) and Features (the areas where users or applications work with those concepts), linking related entries, and checking the result. It carries the judgment the command cannot: when a concept deserves its own entry, whether it is Vocabulary or a Feature, and where a Feature's description must stop so that behavior is described in capabilities instead.
It covers a taxonomy inherited from a parent project: a parent link that passes `taxonomy` brings in the parent's entries, `--scope up` lists and shows them, and an override is my project's own entry at the same path, holding only what it changes. An entry's last part is renamed with `tcw taxonomy rename` and its folder moved with `tcw taxonomy move`, each rewriting the references to it in my project.
Starting a taxonomy from an existing codebase is the `setup` skill, and declaring a parent link is the `configure` skill.
