As a user or agent, I invoke the `work-stage` skill with a stage and a work item to read that lifecycle stage in one piece: TCW's own working document for the stage, followed by the instructions my project adds to it, as `tcw work stage prompt` prints them. It serves every stage — `inbox`, `request`, `spec`, `plan`, `implement`, `verify` and `postmortem` — and needs no work item for `inbox`.
Before anything else, the skill checks its own arguments with `tcw work stage validate`: a missing or unknown stage, a work item given for `inbox`, or an item that does not resolve produces a usage error at the top of the skill instead of broken sections further down. Under a harness that does not run the skill's injected commands, the skill tells me to run that check by hand first.
It only reads. `tcw work stage gate` is still what refuses a stage that may not run, and the skill says so. Under Claude both documents are placed into the skill as it loads; where that does not happen, as under Codex, the skill gives the commands that read the same two documents.
