As a user or agent, I ask the `tcw-commands-drive-work-to-completion` skill to drive an existing work item through the lifecycle stages that remain. The agent works out where the item stands from its type, status and existing artifacts, records each lifecycle artifact in the work item folder as its own commit, and stops for my explicit verification before closeout. It does not complete the item until I approve.

For complex work, `plan.md` can stay short while declaring bounded stage documents: separate documents, one for each slice of the work, listed in a manifest. The agent reads the manifest first and then loads only the stage document for the slice it is working on, including that slice's checks before and after. Dependencies between the documents say what order to work in and what can run in parallel, without becoming formal lifecycle state.
