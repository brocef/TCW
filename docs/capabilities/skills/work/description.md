As a user or agent, I open the `work` skill to learn how to drive the `tcw work` command: filing an item, taking it through its stages from request to qa, resuming it across sessions, splitting it into child items, and making a part in another project from that project. It tells me which stages there are and what each writes, that each stage's instructions come from `tcw work stage prompt <stage> <slug>`, and that `tcw work advance <slug>` moves the item once the stage's output is written, with the gates running on the move. The skill carries the judgment on top of the command: it names `tcw` commands, gets every path from `tcw work path`, and never has me edit the work store by hand where a command does the job.

It tells me how to find my place on an item: `tcw work show` for its stage, request and comments, then the newest handoff for that stage, then the stage's instructions. It also states the rules no project's text changes: a stage may be handed to a subagent but a move never is; searching the board changes nothing; an audit changes nothing without my approval, asked once per kind of change; an item with children is an epic; and a part for another project is made there, through `tcw -C`.

It names items by their full identifiers, `<project>.work/<id-path>`, and teaches how far a command reaches: `--scope` to cover the projects above or below mine and `--project` to keep one of them. A change to another project's item runs in that project, with `tcw -C <folder>`, where `tcw project path <id>` gives the folder. A child is made inside its parent's folder with `--parent` and `--nest`, and an item's folder is moved with `tcw work move` or renamed with `tcw work rename`. Exit 7, a related project or a setting that is not on this machine, is reported with the project it names and how to fetch it, never retried.

**Searching the board and auditing unfinished work** are procedures the agent carries out, because each needs judgment the command cannot supply. The skill reaches each only when I ask, by reading it with `tcw work procedure search` or `tcw work procedure audit-backlog`, which print my project's text under `work.procedures` where it has one and TCW's own otherwise. "Which stage could have caught this?" goes to the postmortem stage, through `tcw work stage prompt postmortem <slug>`.
