As a user or agent, I hand the `work-create` skill an idea for a piece of work — a bug noticed in passing, a follow-up a review left behind, or something a user asked to have tracked — and get exactly one outcome back. It creates a new item, adds the idea to the item that already covers it, revises that item's spec and plan, reports that the work is already tracked or already in progress, files an unclear idea as an inbox arrival, or returns a decision it needs a user to make. A new item records its blockers, reference material and origin.

It searches every unfinished item, inbox arrivals included, before filing anything, and where my project keeps its work in Jira it checks the tickets not yet adopted as well. It runs interactively, as a subagent working from a brief that returns decisions rather than answering for a user, or unattended with defaults when the session was told to work without asking.

How it runs, how it acts on a match and how it reports are TCW's default text, read with `tcw work procedure create-work`, which my project can replace or add to under `work.procedures.create-work`; the one-outcome rule and the search for existing work before filing cannot be replaced.
