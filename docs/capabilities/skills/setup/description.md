As a user or agent, I open the `setup` skill when TCW does not work yet: the `tcw` command-line tool is missing, broken or out of date, a repository does not use TCW, or a TCW project cloned from elsewhere is not working on this machine. It walks first-time setup in order — installing the tool, setting up the repository until `tcw validate` passes, then, optionally, a first taxonomy and a first capabilities ledger — and skips any step that is already done. A request to change how a project that already works is configured goes to the `configure` skill instead.

**Starting a taxonomy.** I ask the `setup` skill to start a taxonomy for my project, and the agent studies my codebase in depth, proposes domain terms, refines them with me, and writes the first taxonomy draft.

**Starting a capabilities ledger.** I ask the `setup` skill to start a capabilities ledger, and the agent studies my codebase in depth, proposes user capabilities, refines them with me, and writes the first capabilities draft. When the project has no taxonomy yet, it starts one first, because capabilities point at taxonomy terms.
