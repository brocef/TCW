As a user or agent, I invoke the `tcw-work-stage` skill with a stage and a work item to read that lifecycle stage in one piece: TCW's own working document for the stage, followed by the instructions my project adds to it, as `tcw work stage prompt` prints them. It serves every stage — `inbox`, `request`, `spec`, `plan`, `implement`, `verify` and `postmortem` — and needs no work item for `inbox`.
It only reads. `tcw work stage gate` is still what refuses a stage that may not run, and the skill says so. Under Claude both documents are placed into the skill as it loads; where that does not happen, as under Codex, the skill gives the commands that read the same two documents.
