As a user or agent, I run a post-mortem on a work item that surfaced a problem — verification rejected it, a spec claim turned out false, or something shipped that should not have — to find which lifecycle stage could first have caught it.
The `post-mortem` skill reads the item's lifecycle artifacts backwards, from the outcome to the original request, using each artifact's `## Notes` as the main trail, and separates "nobody could have known" from "nobody checked" — only the second is something to act on. It writes `post-mortem.md` and never changes the item's status, so it can run both while the item is in review and after it has completed.
Under Claude the analysis can be handed to the read-only `post-mortem` agent; Codex runs the same analysis in its own session by invoking the skill.
How to investigate is TCW's default procedure, which a project replaces under `work.procedures.post-mortem` ([Configure procedures](tcw://C/work/configure-procedures)); the skill and the agent both read it from `tcw work procedure prompt post-mortem`. The order the artifacts are read in, the artifact written and the rule that no status changes stay fixed.
