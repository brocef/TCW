As a user or agent, I open the `tcw-configure` skill when a project where TCW already works should behave differently. It points me to the document that covers each area of configuration: lifecycle bindings (skills or commands run at a stage or transition), how long a hook may run, the templates for lifecycle documents, the Definition of Done, whether transitions commit and publish themselves, the trunk branch, deleting resolved items, documentation entries, an external tracker, where a store lives, connected projects, and inheriting another project's taxonomy or capabilities. Each document says what the setting does, shows its shape, and names the check to run afterwards.
A request that says "set up" but names one of these areas is a change to a project that already works, so it belongs here. Getting TCW working in the first place is the `tcw-setup` skill.
