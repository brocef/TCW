As a user or agent, I hand the `tcw-work-create` skill an idea for a piece of work — a bug noticed in passing, a follow-up a review left behind, or something a user asked to have tracked — and get exactly one outcome back. It creates a new item, adds the idea to the item or work inbox entry that already covers it, revises that item's spec and plan, reports that the work is already tracked or already in progress, defers an unclear idea to the work inbox, or returns a decision it needs a user to make. A new item records its blockers, reference material and origin.
It checks the work inbox as well as open items before filing anything, and from inside an implementation worktree it uses the primary checkout's board. It runs interactively, as a subagent working from a brief that returns decisions rather than answering for a user, or unattended with defaults when the session was told to work without asking.
How it runs, which checkout it files from, how it acts on a match and how it reports are TCW's default text, which my project can replace or add to under `work.procedures.create-work`; the one-outcome rule and the search for existing work before filing cannot be replaced.
