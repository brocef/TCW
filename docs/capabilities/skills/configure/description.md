As a user or agent, I open the `configure` skill when a project where TCW already works should behave differently. It points me to the document that covers each area of configuration: the stages a project uses and the text and commands bound to each stage, how long a hook may run, procedures, tags, the Jira backend and how stages map to Jira statuses, documentation entries, where a store lives (a path relative to the project, or a `.path` address), a project's parent links and what each passes down, the manifests that say where each related project is, the configuration a parent passes down, and a person's own configuration and the environment variables that override a setting for one project, with one table of every key and who may set it. Each document says what the setting does, shows its shape, and names the check to run afterwards.
A request that says "set up" but names one of these areas is a change to a project that already works, so it belongs here. Getting TCW working in the first place is the `setup` skill.
