As a user or agent, I ask the `commands-pause-work` skill to stop the work in hand — because I am about to lose my connection, restart, or pick the work up on another machine. The agent brings what it is doing to a coherent resting point rather than halting mid-edit.

It then writes a handoff for each affected item, holding whatever resuming needs, so the work can be resumed from the board rather than from a conversation that may be gone. The handoff goes in the folder of the stage the item is at, as the new file `tcw work path <slug> <stage> --handoff` names; where the backend keeps that stage, it is a comment whose first line is `Handoff`; at the inbox, nothing is written. What a handoff holds, and anything more my project wants done on a pause, come from the `pause-work` procedure, which my project can replace under `work.procedures.pause-work`.

It moves no item, so each keeps its stage. Then it reports where things stand and falls silent until I say to continue. Resuming reads the newest handoff for the stage; handoffs are never deleted.
