As a user or agent, I ask the `commands-pause-work` skill to stop the work in hand — because I am about to lose my connection, restart, or pick the work up on another machine. The agent brings what it is doing to a coherent resting point rather than halting mid-edit.

It then writes a handoff for each affected item, holding whatever resuming needs, and keeps it where a fresh session, possibly on another machine, can find it. By default that is a new file in the folder of the stage the item is at, as `tcw work path <slug> <stage> --handoff` names, shared the way my project shares its files, where my instructions allow; where the backend keeps that stage, a comment whose first line is `Handoff`; at the inbox, nothing. What a handoff holds, where it goes, and anything more my project wants done on a pause come from the `pause-work` procedure, which my project can replace under `work.procedures.pause-work`.

It moves no item, so each keeps its stage. An agent reporting to another agent sends that agent its report. The agent reporting to me ends with a single resume message I can paste into a fresh session to pick all of the work back up, starting agents again where the work was split between them; copying it is the one way certain to carry anything across. Then it falls silent until I say to continue. Handoffs are never deleted.

A pause may reach an agent as an interruption followed by a message. An interrupted agent assumes I interrupted it, reads the pending message and pauses, rather than carrying on or treating itself as finished; and an agent relaying the pause to others does not count one as done and idle until more than ten minutes pass without a message or confirmation from it.
