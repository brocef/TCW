As a user or agent, I open the `capabilities` skill to learn how to keep my project's capabilities ledger, the record of what a user can do, through the `tcw capabilities` command. It covers a work item that changes what users can do: checking the change against the capabilities already recorded, declaring the capabilities it adds, changes or removes in the item's `capabilities.yaml` while the spec is written, and linking each capability to a taxonomy Feature.

The records themselves change during implement, in the same change as the code: a new capability is added with the status it really has (`tcw capabilities add <path> "<Name>" --status Supported`), and a changed or removed one is edited or deleted then. The move out of implement checks that every declared record is in place and not `Missing`, so nothing is flipped at completion. On a project with no ledger of its own the declaration can name a child project's ledger, and the skill covers getting the agreed wording for a capability from the parent project when several projects share one product.

Starting a ledger from an existing codebase is the `setup` skill, and declaring that a project inherits another project's capabilities is the `configure` skill.
