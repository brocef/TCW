As a user or agent, I ask the `commands-drive-work-to-completion` skill to take an existing work item through the stages that remain: implement, review and qa. The agent finds where the item stands with `tcw work show`, reads each stage's instructions with `tcw work stage prompt <stage> <slug>`, writes what the stage asks for, and moves the item on with `tcw work advance`. A rejected review or qa sends the item back to implement for another round.

Review is done by a reviewer who did not write the code: a subagent where the harness can start one, which reads the review stage's instructions and recommends a verdict that the agent then writes as the review round. At qa, the agent follows the qa stage's instructions: with TCW's own text on files, it runs the QA plan's scenarios and records the verdict itself; where my project's qa instructions say a person decides, or where the backend keeps qa, it asks me and records my decision, never choosing the verdict for me.
