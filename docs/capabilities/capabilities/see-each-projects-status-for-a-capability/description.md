As a user of a project with children, I run `tcw capabilities list --scope down` or `--scope all` to see each capability once, with the status each project in the scope gives it: its record carries `statuses`, one `{"project", "status", "inherited", "full-id"}` entry per covered project, in scope order. `inherited` marks a status a project takes from the project it inherits from without ruling on the capability itself. `full-id` is the full identifier of the object the project's view comes from: its own object at the path when it has one, even one that sets no Status, and otherwise the object it inherits. `tcw capabilities show <path> --scope down` prints the same as a `status by project:` block, one line per status naming the projects that give it, with `(inherited)` beside those that only inherit it, and a line naming each project that could not be read.

`--status <status>` keeps a capability when any covered project gives it that status. `--project <id>` keeps one project's own capabilities and shows no status block. The local web app shows the same counts on each capability row, as `Missing(1), Supported(1)`, and lists each status with its projects on the capability's page.
