As a user, I run `tcw capabilities show <path>` to read a capability: its full identifier, the project that owns it, its name, metadata fields and body. The text form starts with `full-id: <project>.capabilities/<id-path>` and `owner: <project>`. I name the capability by its full identifier, its `tcw://` address, or its id-path alone, which finds this project's own capability first and otherwise the one it inherits at that path, with this project's override applied. An inherited capability is named by the full identifier of the project it comes from (`shared.capabilities/web/login`), and a capability of any other project TCW can locate can be read the same way. `--json` prints `{"schema": 2, "capability": {...}}` with the same content, under `full-id` and `owner`. A path that matches no capability exits 4; a bare id-path that matches capabilities in more than one inherited project is a usage error (exit 2) asking me to write the full identifier; and a project ID TCW cannot find exits 1.
