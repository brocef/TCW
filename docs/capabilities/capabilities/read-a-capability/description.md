As a user, I run `tcw capabilities show <path>` to read a capability: its full identifier, the project that owns it, its name, metadata fields and body. The text form starts with `full-id: <project>.capabilities/<id-path>` and `owner: <project>`. I name the capability by its full identifier, its `tcw://` address, or its id-path alone. With no `--scope`, an id-path names my project's own capability there; one my project only inherits is not found, and the message names its full identifier and says to add `--scope up`. With `--scope up`, `down` or `all`, an id-path names the one capability at that path in my project's view: combined field by field from my project's own capability there, if any, and the ones it inherits, and named by the full identifier of the nearest project that has one. A full identifier names that project's own capability as that project sees it, so `shared.capabilities/web/login` is `shared`'s capability, never my override of it, and a capability of any other project TCW can locate can be read the same way. When the capability overrides one, the text form prints `overrides: <full id>` after `owner:` and `parent:`, and the record carries `overrides`, a full identifier or `null`; it carries no `id`. `--json` prints `{"schema": 2, "capability": {...}}` with the same content, under `full-id` and `owner`. A path that matches no capability exits 4, and a project ID TCW cannot find exits 1. An id-path is never ambiguous: where two parents that do not inherit from each other both have a capability at it, the one later in my project's load order is used, with a warning on standard error.

A capability's record carries its `parent`, and `prependedDocs` and `appendedDocs` name files in its `resources/` folder.

When a parent is not on this machine, `show` of one of my project's own capabilities still works: it prints the capability's own declaration alone, with `partial: inherited content could not be read` in place of an `overrides:` line, and the JSON record carries `"partial": true` and no `overrides`. A warning on standard error says only my project's own declarations are shown, and it exits 0. `show` of a capability my project inherits stops with exit 7.

Under `--scope down` or `all`, `show` also prints `overridden by:`, naming each override of the capability in the projects the scope covers, and a `status by project:` block, each status with the projects that give it.
