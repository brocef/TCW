As a user, I run `tcw capabilities list` to see every capability's full identifier, one per line, each path once. With no `--scope`, the scope is `own`: only my project's own capabilities, overrides included. `--scope up` lists my project's view, what it holds and what it inherits: the capability at a path is combined from my project's own capability there, if any, and the ones it inherits. `--status <status>` keeps only capabilities with that status, and `--namespace <folder>` only those under one namespace folder. `--json` prints `{"schema": 2, "capabilities": [...]}`, giving each capability's full identifier, owner, parent, name and status, and `overrides`: the full identifier of the capability it overrides, or `null`. No record carries an `id`. Where two parents that do not inherit from each other both have a capability at one path, the one later in my project's load order is used, and a warning on standard error says so before the list.

When a parent is not on this machine, `list` still works: each JSON record carries `"partial": true` and no `overrides`, a warning on standard error says only my project's own declarations are shown, and it exits 0. `list --scope up` stops with exit 7.

`--scope down` adds the capabilities of the projects below mine, and `--scope all` both directions; each row is one capability with every override of it in the scope, and its record carries `overridden-by`, the full identifiers of those overrides, and `statuses`, the status each covered project gives it. `--project <id>` keeps only one covered project's own capabilities. A project the scope covers that is not on this machine, or cannot be read, is named on standard error as `warning: '<id>' is unavailable, so …`, with its reason, and in the `--json` document's `projects`; the command still exits 0. The TCW 3.x option that limited a listing to my project's own capabilities is refused with exit 2, since `--scope own`, the default, already does that; [the 3.x to 4.0 migration guide](../../../migration-guide-3.X-to-4.0.0.md) maps it.
