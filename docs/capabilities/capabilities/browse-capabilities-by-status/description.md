As a user, I run `tcw capabilities list` to see every capability's full identifier, one per line, my project's own and inherited alike, each path once: the capability at a path is combined from my project's own capability there, if any, and the ones it inherits. `--status <status>` keeps only capabilities with that status, and `--namespace <folder>` only those under one namespace folder. With no `--scope`, the scope is `own` and the list holds only my project's own capabilities, overrides included; `--scope up` adds the ones it inherits. `--json` prints `{"schema": 2, "capabilities": [...]}`, giving each capability's full identifier, owner, parent, name and status, and `overrides`: the full identifier of the capability it overrides, or `null`. No record carries an `id`. Where two parents that do not inherit from each other both have a capability at one path, the one later in my project's load order is used, and a warning on standard error says so before the list.

When a parent is not on this machine, `list` still works: each JSON record carries `"partial": true` and no `overrides`, a warning on standard error says only my project's own declarations are shown, and it exits 0. `list --scope up` stops with exit 7.
