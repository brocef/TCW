As a user, I get the `tcw` CLI on my PATH without running anything: the plugin installs the published `tcw-cli` from PyPI via pipx when a session starts, and reinstalls it when a plugin update changes the plugin's version, so the command never goes stale behind the skills that drive it. In Codex, where there is no session-start hook, I ask the agent to run the `tcw-plugin` setup, which runs the same script. This means the first session after I install or update the plugin needs network access; if PyPI cannot be reached the session tells me so in one line and points me at the doctor. A `tcw` the plugin did not install — a developer's `pip install -e` checkout, or one whose owning interpreter it cannot identify — is left alone, and so is a machine without `pipx`; `/tcw-doctor` (or the `tcw-plugin` skill) handles those and anything else the automatic path skips.
