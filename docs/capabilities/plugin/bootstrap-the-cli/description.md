As a user, I get the `tcw` CLI on my PATH without running anything: the plugin installs the published `tcw-cli` from PyPI via pipx when a session starts, and reinstalls it when a plugin update changes the plugin's version. That install takes the newest release on PyPI, and a `tcw` the plugin did not install is never replaced, so the CLI can still come from a different release than the skills; when it does, the session says so and names the command that lines them up. In Codex, where there is no session-start hook, I ask the agent to run the `setup` skill, which runs the same script. This means the first session after I install or update the plugin needs network access; if PyPI cannot be reached the session tells me so in one line, and names the one command that installs it by hand. A `tcw` the plugin did not install — a developer's `pip install -e` checkout, or one whose owning interpreter it cannot identify — is left alone, and so is a machine without `pipx`; the `setup` skill handles those and anything else the automatic path skips.
