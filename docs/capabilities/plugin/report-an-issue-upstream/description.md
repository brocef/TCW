As a user or agent, I send feedback about TCW itself — a `tcw` bug, a rough edge in a skill, a feature idea — to the project's GitHub tracker, so that it reaches the maintainers instead of being filed into my own `tcw work` store, which tracks changes to my project and is not a channel upstream.
The `tcw-report` skill hands over a ready-to-fill skeleton for each kind of report: a bug, with an environment block and reproduction steps, or a suggestion, with its motivation and what it would unlock. It asks for the installed version first, because most bug reports are unactionable without it, and it asks me to search the open and recently closed issues so a duplicate becomes added detail on the issue that already exists.
The tracker is public and the project I am reporting from may not be, so the report is written from a generic example that mirrors my setup rather than from the real thing: the command's shape and flags, the error's type and message, and the sequence that triggered them all survive, under names that are not mine. Reproduction steps starting from a clean install and a scratch project are worth sketching, and can be handed to a subagent working in a temporary directory so nothing runs in my own checkout. All of it is guidance — what goes into the report is my call, and I can include a real detail when I want it there.
There is no slash command for this one; Claude and Codex both invoke the `tcw-report` skill directly.
