As a user, I run `tcw taxonomy list` to see every entry's full identifier, one per line, each path once. With no `--scope`, the scope is `own`: only my project's own entries, overrides included. `--scope up` lists my project's view, what it holds and what it inherits: the entry at a path is combined from my project's own entry there, if any, and the ones it inherits. `--json` prints `{"schema": 2, "terms": [...]}`, giving each entry's full identifier, owner, parent, name, kind (`Vocabulary` or `Feature`), and `overrides`: the full identifier of the entry it overrides, or `null`. Where two parents that do not inherit from each other both have an entry at one path, the one later in my project's load order is used, and a warning on standard error says so before the list.

When a parent is not on this machine, `list` still works: each JSON record carries `"partial": true` and no `overrides`, a warning on standard error says only my project's own declarations are shown, and it exits 0. `list --scope up` stops with exit 7.

Only a folder holding `tcw-taxonomy.yaml` is a term; a folder with none groups terms and is never listed.

`--scope down` adds the entries of the projects below mine, and `--scope all` both directions; each row is one entry with every override of it in the scope, and its record carries `overridden-by`, the full identifiers of those overrides. `--project <id>` keeps only one covered project's own entries. A project the scope covers that is not on this machine, or cannot be read, is named on standard error as `warning: '<id>' is unavailable, so …`, with its reason, and in the `--json` document's `projects`; the command still exits 0. `list --local` is removed: it is refused with exit 2, since `--scope own`, the default, already lists only my project's own entries.
