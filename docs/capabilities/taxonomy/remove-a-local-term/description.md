As a user, I run `tcw taxonomy rm <path>` to delete a local term. The path addresses a term inside the taxonomy tree and nothing outside it — one that tries to escape (`../capabilities/…`) matches no term and deletes nothing. The tool refuses (exit 3) to remove an inherited term, a term with other terms nested under it, and a term another local term still names in `relatesTo` or a feature's `vocabulary`; the refusal names what is in the way and deletes nothing, so `tcw validate` never fails because of a removal that succeeded. References from the capabilities ledger (`Subject`, `Feature`) are not checked here; `tcw validate` reports those.

Removing a term deletes its files and nothing else: each file removed is named on standard error, nothing is staged or committed, and a term whose files git has never seen is removed like any other.
