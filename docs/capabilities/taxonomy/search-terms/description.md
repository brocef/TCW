As a user, I run `tcw taxonomy search <query>` to find entries whose name or description contains the text, ignoring case, among my project's own entries by default; `--scope up` searches my project's view, its own entries and the ones it inherits, each path once and matched on the combined entry, and `--scope down` or `all` also the entries of the projects below it. `--project <id>` keeps one covered project's own entries. It prints one full identifier per line, or with `--json`, `{"schema": 2, "terms": [...]}`, each record carrying `overrides`, a full identifier or `null`. Where two parents that do not inherit from each other both have an entry at one path, a warning on standard error says which is used. No match prints nothing and exits 0. When a parent is not on this machine, a search under `--scope up`, `down` or `all` stops with exit 7.
