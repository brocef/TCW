As a user, I run `tcw taxonomy show <path>` to read an entry: its full identifier, the project that owns it, its name, kind, feature vocabulary refs, relatesTo links, attachments, and its description. The text form starts with `full-id: <project>.taxonomy/<id-path>` and `owner: <project>`. I name the entry by its full identifier, its `tcw://` address, or its id-path alone, which finds this project's own entry first and otherwise the one it inherits at that path. An inherited entry is named by the full identifier of the project it comes from (`shared.taxonomy/invoice`), and an entry of any other project TCW can locate can be read the same way. `--json` prints `{"schema": 2, "term": {...}}` with the same fields, under `full-id` and `owner`. A path that matches no entry exits 4; a bare id-path that matches entries in more than one inherited taxonomy is a usage error (exit 2) asking me to write the full identifier; and a project ID TCW cannot find exits 1.
