As a user, I run `tcw taxonomy add <name>` to register a vocabulary term or a feature, with optional `--slug <slug>`, `--parent <path>`, `--flat`, `--kind vocabulary|feature` and `--vocab <ref>` (repeat it for more), and the entry's description piped on standard input. The slug is the entry's path identity; adding under a parent nests it. Without `--slug` the slug is made from the name; a `--slug` I give must already be in that form, lowercase letters and digits in words joined by single hyphens, so one with a space, a capital letter or a `/` is a usage error (exit 2) and nothing is written. Nesting is `--parent`'s job, never the slug's. On success the command prints the new entry's qualified path on standard output, and names each file it wrote on standard error.

A `--vocab <ref>` is a term path (`alpha/zeta`), an `<alias>/<path>` into an inherited taxonomy, or a leaf slug that is unique across the local tree — a unique leaf slug is accepted and stored as its full path. The command refuses a ref that does not resolve or is ambiguous, one that names a feature where a vocabulary term is expected, and a feature carrying no vocabulary ref (usage errors, exit 2); it also refuses a name already taken (exit 3). A refused add writes nothing. So vocabulary entries must be registered before the features that name them.

Adding a term writes files and nothing else: it stages and commits nothing, and works the same inside or outside a git repository. A write that fails part-way is rolled back: whatever the command created is removed, and whatever was already there is left as it was.

A term is a folder holding `tcw-taxonomy.yaml`. `tcw taxonomy add --parent` writes `parent:` and makes the folder inside the parent's only when the parent is a term of this project's own store and `--flat` is not given; under an inherited or another project's parent the folder is made at the top of the store and a `not nested:` line says so, and `--flat` without `--parent` is a usage error (exit 2); a term's other files go in its `resources/` folder.

At a path my project already inherits a term at, `add` writes an override (see [Override an inherited term](tcw://C/taxonomy/override-an-inherited-term)): my own term there, holding only what differs from the inherited term, never `relatesTo`, and standard error says `<new full id> overrides <inherited full id>`. When nothing given differs, it is refused (exit 3) and writes nothing.
